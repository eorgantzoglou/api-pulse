# API Pulse Phase 2 — The Site — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static site over the data the pipeline already publishes, that answers "which of these 1,755 APIs actually works?" in one screen, and shows where the upstream README's own metadata disagrees with what we measured.

**Architecture:** No build step. One `index.html`, a handful of ES modules, one stylesheet, one self-hosted font, all served by GitHub Pages from the same repository that holds the data. The page fetches `data/catalog.json` and `data/status.json` from its own origin (137 KB gzipped for both), joins them on `id`, and does all filtering, sorting and searching in memory. Nothing is generated at deploy time; nothing is fetched from a third party at runtime.

**Tech Stack:** HTML, CSS, vanilla ES modules. `node --test` for unit tests (Node's built-in runner — no npm install, no `package.json` dependencies, no lockfile). GitHub Pages via Actions.

## Global Constraints

- **No build step, no npm dependencies, no lockfile.** If a task seems to need a bundler, it is wrong. The same reasoning that made the pipeline serverless applies harder here: this must still work untouched in late 2027.
- **Nothing loads from a third-party origin at runtime.** Fonts are self-hosted in the repo. No CDN, no Google Fonts link, no analytics.
- **Phase 2 is purely additive. Do not modify `api_pulse/`, `tests/`, or `pyproject.toml`.** The pipeline is in production and its 110 tests must keep passing untouched.
- The site reads only `data/catalog.json` and `data/status.json`. It does **not** read `history.json` — `status.json` already embeds each entry's 90-day series in its `history` field.
- Every colour that carries meaning must pass `scripts/validate_palette.js` from the `dataviz` skill in **both** light and dark mode before it ships. Compute it; do not eyeball it.
- Keyboard reachable, visible focus, `prefers-reduced-motion` respected, and no information conveyed by colour alone.
- Commit after every task.

## The data, as it actually exists

Measured from the live files on 2026-09-09, not assumed:

```
data/catalog.json   496 KB raw   90 KB gzip   {generated, schema, count, entries[]}
data/status.json    502 KB raw   47 KB gzip   {generated, schema, entries[]}
```

| `catalog.json` entry | `status.json` entry |
|---|---|
| `id`, `name`, `url`, `description`, `category`, `auth`, `https`, `cors` | `id`, `state`, `status_code`, `final_url`, `response_ms`, `tls_valid`, `cors_header`, `failing_streak`, `likely_dead`, `history` |

They join on `id`. 1,755 entries, 51 categories. `auth` takes exactly five values: `""`, `apiKey`, `OAuth`, `User-Agent`, `X-Mashape-Key`. `history` is a string of one character per day, oldest first, at most 90 long — `L A R C N S T D U X` for the ten states and `.` for a day with no data.

Day-one state distribution, which the design has to survive:

```
live 1366 (77.8%) · not_found 113 · auth_required 112 · timeout 40
unreachable 39 · dns_failure 37 · server_error 17 · tls_invalid 13
rate_limited 10 · client_error 8          reachable 85.2% · failing 14.8%
```

Note `likely_dead` is `false` for every entry until three consecutive failing days have accumulated. The site must not present "0 dead APIs" as a finding — see Task 4.

## Design plan

### The problem with the obvious approach

Ten states is too many for colour. The `dataviz` non-negotiables are explicit: categorical hues are assigned in fixed order and never cycled, a ninth series is never a generated hue, and **status colours are reserved** and ship with a label rather than colour alone. Ten hues across 90 × 1,755 cells would be unreadable, indefensible under colour-vision deficiency, and would encode a false claim — that all ten states are peers, when they are not.

So the states collapse to a **four-level status scale plus a neutral**, and the exact state travels as text:

| Level | States | What it means |
|---|---|---|
| **Healthy** | `live` | Answered normally |
| **Gated** | `auth_required`, `rate_limited`, `client_error` | Answered, but refused us — the domain is alive |
| **Transient** | `server_error`, `timeout` | Failing in a way that often recovers |
| **Hard** | `not_found`, `dns_failure`, `unreachable`, `tls_invalid` | Failing in a way that usually does not |
| **No data** | `.` | Not probed that day |

Four levels, ordered, with a real semantic gradient. The exact state appears in the row, in the tooltip, and in the table view. Colour is never the only carrier.

### Tokens

**Colour.** Status owns the warning/danger hues, so the interactive accent must live somewhere else entirely — otherwise a focus ring reads as an error. The accent is therefore violet, chosen because it is the one region of the wheel the status scale does not occupy.

The exact status hexes are **not fixed here on purpose**: Task 1 derives them and runs the validator, because the six checks (lightness band, chroma floor, adjacent-pair CVD separation, normal-vision floor, contrast) decide which steps are legal against each surface. What is fixed is the structure:

```
--surface        light: cool near-white, not cream   dark: deep slate, not #000
--surface-raised one step from surface, both modes
--ink            primary text        --ink-2 secondary        --ink-3 muted
--accent         violet — interaction only, never status
--ok --gated --transient --hard --nodata   the five strip levels, validated per mode
```

Light and dark are **stepped separately from the same ramps and validated separately**, not flipped.

**Type.** One variable family: **Recursive**, self-hosted as a single woff2 in `site/fonts/`. It carries both a sans and a mono along one axis, which is exactly this page's need — prose in sans, and the strip, ids, status codes and response times in mono where character alignment does real work. One family, two voices, no arbitrary pairing. It is also not the Inter/Geist default.

Monospace is used only where alignment is functional. Labels are not monospace; that is decoration.

**Layout.** Left-aligned throughout. Line length capped below 80 characters for prose.

### The hero

The default treatment — a big number, a small label, supporting stats, a gradient — is what every generated dashboard does. This dataset can do something no other dataset can:

```
┌──────────────────────────────────────────────────────────────┐
│  1,755 public APIs, probed this morning                      │
│                                                              │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░▓▓▓▓▓▓▓▓▓   │
│  ▓▓▓▓▓▓▓▓░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   │  ← every entry,
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   │    one cell
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   │
│                                                              │
│  1,496 answered · 259 did not · 14.8% of the list is broken  │
└──────────────────────────────────────────────────────────────┘
```

**The whole catalogue as one field.** 1,755 cells, one per API, coloured by today's level, ordered so failures cluster rather than scatter into noise. It is a portrait of the commons: you see the 14.8% as an actual quantity of damage, not a percentage you have to imagine. Hovering a cell names the API; clicking scrolls to its row; filtering dims the cells that drop out, so the field visibly carves as you narrow.

It is the data, at full resolution, as the image. Nothing decorative, and nothing another project could copy without doing the measurement first.

### Principles

1. **The strip is the product.** Everything else is chrome around a 90-day trace. Spend the boldness there and keep the rest quiet.
2. **Never assert more than we measured.** The README's honesty constraint is a design constraint: this page says "the documentation link answered", never "the API works".
3. **Absence is information.** A `.` in a strip is a day we did not look, and it must look different from a day that failed — not similar-but-lighter.
4. **The default view is opinionated.** Broken entries are hidden by default. That is the entire reason this exists rather than the README.

### Reviewing this plan against the generic default

Working the brief cold — "dashboard for API uptime data" — produces: dark background, acid-green/red status dots, a card grid of KPI tiles, Inter, a big percentage with a gradient. Four of the five specifics above were changed away from that:

- The KPI-tile grid is gone; the hero is the dataset itself rendered at full resolution.
- Ten status hues collapse to four ordered levels, because the data is ordinal and CVD-safety is computable.
- The accent is moved off the status wheel entirely, so interaction never reads as alarm.
- Type is one variable family carrying both voices, chosen for a functional reason, rather than a sans + unrelated mono pairing.

Retained from the default: dark mode exists, and failures are red-ward. Both are correct here — one because developers read in the dark, the other because it is the near-universal convention for harm and breaking it would cost comprehension for no gain.

```js
// The ten probe states collapse to four ordered levels. Ten hues would be
// unreadable and indefensible under colour-vision deficiency; the exact state
// always travels alongside as text, so colour is never the only carrier.
export const LEVELS = ["ok", "gated", "transient", "hard"];

const STATE_LEVEL = {
  live: "ok",
  auth_required: "gated",
  rate_limited: "gated",
  client_error: "gated",
  server_error: "transient",
  timeout: "transient",
  not_found: "hard",
  dns_failure: "hard",
  unreachable: "hard",
  tls_invalid: "hard",
};

export const CHAR_STATE = {
  L: "live", A: "auth_required", R: "rate_limited", C: "client_error",
  N: "not_found", S: "server_error", T: "tls_invalid", D: "dns_failure",
  U: "unreachable", X: "timeout",
};

export const STATE_LABEL = {
  live: "Answered",
  auth_required: "Needs a key",
  rate_limited: "Rate limited",
  client_error: "Refused the request",
  not_found: "Page is gone",
  server_error: "Server error",
  timeout: "Timed out",
  tls_invalid: "Certificate problem",
  dns_failure: "Domain does not resolve",
  unreachable: "Nothing listening",
};

// A state this build has never heard of is a later schema, not a healthy API.
// Failing towards "transient" keeps it visible without asserting it is dead.
export function levelOf(state) {
  return STATE_LEVEL[state] || "transient";
}

export function levelOfChar(ch) {
  if (ch === ".") return "nodata";
  const state = CHAR_STATE[ch];
  return state ? levelOf(state) : "nodata";
}
```

- [ ] **Step 4: Write `site/js/data.js`**

```js
const CATALOG = "./data/catalog.json";
const STATUS = "./data/status.json";

async function getJson(fetchImpl, url) {
  const res = await fetchImpl(url);
  if (!res.ok) throw new Error(`Could not load ${url} (HTTP ${res.status})`);
  return res.json();
}

// The catalogue is the source of truth for what exists. An entry with no status
// row is kept and rendered as unmeasured rather than silently vanishing — the
// alternative hides entries precisely when something has gone wrong upstream.
export async function load(fetchImpl = fetch) {
  const [catalog, status] = await Promise.all([
    getJson(fetchImpl, CATALOG),
    getJson(fetchImpl, STATUS),
  ]);

  const byId = new Map(status.entries.map((s) => [s.id, s]));
  const entries = catalog.entries.map((c) => ({
    ...c,
    ...(byId.get(c.id) || {}),
    history: (byId.get(c.id) || {}).history || "",
  }));

  return { generated: status.generated || catalog.generated, entries };
}
```

```js
import { levelOf, LEVELS } from "./levels.js";

// An empty auth filter means "any". "No key needed" is a real, and the most
// commonly wanted, selection, so it gets its own sentinel rather than colliding
// with the any-value.
export const AUTH_NONE = "none";

export const DEFAULT_QUERY = {
  text: "", category: "", auth: "", https: false, cors: "",
  hideBroken: true, sort: "reliability",
};

const SORTS = new Set(["reliability", "name", "speed"]);
const BROKEN = new Set(["transient", "hard"]);

export function apply(entries, query) {
  const q = { ...DEFAULT_QUERY, ...query };
  const text = q.text.trim().toLowerCase();

  const rows = entries.filter((e) => {
    if (q.hideBroken && e.state && BROKEN.has(levelOf(e.state))) return false;
    if (q.category && e.category !== q.category) return false;
    if (q.auth && e.auth !== (q.auth === AUTH_NONE ? "" : q.auth)) return false;
    if (q.https && !e.https) return false;
    if (q.cors && e.cors !== q.cors) return false;
    if (text) {
      const hay = `${e.name} ${e.description}`.toLowerCase();
      if (!hay.includes(text)) return false;
    }
    return true;
  });

  // Decorate-sort-undecorate keeps the sort stable across engines and keeps the
  // comparator cheap: level lookup happens once per row, not once per comparison.
  const key = (e) => {
    if (q.sort === "name") return e.name.toLowerCase();
    if (q.sort === "speed") return e.response_ms == null ? Infinity : e.response_ms;
    const rank = e.state ? LEVELS.indexOf(levelOf(e.state)) : LEVELS.length;
    return rank < 0 ? LEVELS.length : rank;
  };

  return rows
    .map((e, i) => ({ e, i, k: key(e) }))
    .sort((a, b) => (a.k < b.k ? -1 : a.k > b.k ? 1 : a.i - b.i))
    .map((d) => d.e);
}

export function facets(entries) {
  const uniq = (xs) => [...new Set(xs.filter(Boolean))].sort((a, b) => a.localeCompare(b));
  return {
    categories: uniq(entries.map((e) => e.category)),
    auths: uniq(entries.map((e) => e.auth)),
  };
}

export function toHash(query) {
  const q = { ...DEFAULT_QUERY, ...query };
  const p = new URLSearchParams();
  for (const [k, v] of Object.entries(q)) {
    if (v !== DEFAULT_QUERY[k]) p.set(k, String(v));
  }
  const s = p.toString();
  return s ? `#${s}` : "";
}

export function fromHash(hash) {
  const p = new URLSearchParams((hash || "").replace(/^#/, ""));
  const q = { ...DEFAULT_QUERY };
  for (const k of Object.keys(DEFAULT_QUERY)) {
    if (!p.has(k)) continue;
    const raw = p.get(k);
    q[k] = typeof DEFAULT_QUERY[k] === "boolean" ? raw === "true" : raw;
  }
  if (!SORTS.has(q.sort)) q.sort = DEFAULT_QUERY.sort;
  return q;
}
```

```js
import { levelOfChar, CHAR_STATE, STATE_LABEL } from "./levels.js";

export const WINDOW = 90;

// Left-pad rather than right-pad: every strip must end on today, so a column
// means the same date in every row. Short histories are young entries, not
// failing ones.
export function stripCells(history, window = WINDOW) {
  const recent = (history || "").slice(-window);
  const padded = ".".repeat(Math.max(0, window - recent.length)) + recent;
  return [...padded].map((ch, i) => ({
    level: levelOfChar(ch),
    state: CHAR_STATE[ch] || null,
    offsetFromToday: padded.length - 1 - i,
  }));
}

export function renderStrip(history) {
  const wrap = document.createElement("div");
  wrap.className = "strip";
  wrap.setAttribute("role", "img");

  const cells = stripCells(history);
  const measured = cells.filter((c) => c.level !== "nodata");
  const ok = measured.filter((c) => c.level === "ok" || c.level === "gated").length;
  wrap.setAttribute(
    "aria-label",
    measured.length
      ? `Answered on ${ok} of the last ${measured.length} days probed`
      : "Not probed yet"
  );

  for (const cell of cells) {
    const el = document.createElement("span");
    el.className = `cell cell--${cell.level}`;
    if (cell.state) {
      const when = cell.offsetFromToday === 0 ? "today" : `${cell.offsetFromToday} days ago`;
      el.title = `${STATE_LABEL[cell.state]} — ${when}`;
    }
    wrap.append(el);
  }
  return wrap;
}
```

- [ ] **Step 4: Write `site/js/table.js`**

Each row carries: name (linking to `url`), category, the strip, the current state **as text** beside its colour, response time in mono, and the auth requirement.

1,755 rows × 90 cells is 158,000 nodes rendered eagerly, which janks on mid-range hardware. Render in windows instead — a chunk immediately, the rest as a sentinel scrolls into view. No virtual-list dependency, and the DOM stays real so Ctrl-F and screen readers still work.

```js
import { renderStrip } from "./strip.js";
import { STATE_LABEL } from "./levels.js";

const CHUNK = 100;

function row(entry) {
  const el = document.createElement("article");
  el.className = "row";
  el.id = `row-${entry.id}`;
  el.tabIndex = -1;

  const link = document.createElement("a");
  link.className = "row__name";
  link.href = entry.url;
  link.rel = "noopener noreferrer";
  link.textContent = entry.name;

  const meta = document.createElement("p");
  meta.className = "row__meta";
  meta.textContent = entry.description;

  const state = document.createElement("span");
  // The label is the carrier; the dot beside it is reinforcement, never the
  // only signal.
  state.className = `row__state row__state--${entry.state || "unknown"}`;
  state.textContent = entry.state ? STATE_LABEL[entry.state] : "Not probed yet";

  const streak = document.createElement("span");
  streak.className = "row__streak";
  streak.textContent = entry.failing_streak > 0 ? `failing for ${entry.failing_streak} days` : "";

  const speed = document.createElement("span");
  speed.className = "row__speed mono";
  speed.textContent = entry.response_ms == null ? "" : `${entry.response_ms} ms`;

  const auth = document.createElement("span");
  auth.className = "row__auth";
  auth.textContent = entry.auth ? entry.auth : "no key needed";

  el.append(link, meta, renderStrip(entry.history), state, streak, speed, auth);
  return el;
}

export function renderRows(container, entries) {
  container.replaceChildren();
  let next = 0;

  const sentinel = document.createElement("div");
  sentinel.className = "sentinel";

  const paint = () => {
    const slice = entries.slice(next, next + CHUNK);
    if (!slice.length) {
      observer.disconnect();
      sentinel.remove();
      return;
    }
    const frag = document.createDocumentFragment();
    for (const e of slice) frag.append(row(e));
    container.insertBefore(frag, sentinel);
    next += slice.length;
  };

  const observer = new IntersectionObserver((es) => {
    if (es.some((e) => e.isIntersecting)) paint();
  }, { rootMargin: "600px" });

  container.append(sentinel);
  paint();
  observer.observe(sentinel);
}
```

- [ ] **Step 1: Build the field**

One cell per entry, ordered by level (healthy first) then by name, so failures cluster into a visible band instead of scattering into noise. The field is built once from the full entry list and never rebuilt — filtering dims cells rather than reflowing them, so it reads as carving one image rather than drawing a different one.

```js
import { levelOf, LEVELS, STATE_LABEL } from "./levels.js";

const cells = new Map(); // id -> element, so updates never re-query the DOM

export function renderMosaic(container, entries) {
  container.replaceChildren();
  cells.clear();

  const ordered = [...entries].sort((a, b) => {
    const ra = a.state ? LEVELS.indexOf(levelOf(a.state)) : LEVELS.length;
    const rb = b.state ? LEVELS.indexOf(levelOf(b.state)) : LEVELS.length;
    return ra - rb || a.name.localeCompare(b.name);
  });

  const frag = document.createDocumentFragment();
  for (const e of ordered) {
    const cell = document.createElement("button");
    cell.type = "button";
    cell.className = `mosaic__cell mosaic__cell--${e.state ? levelOf(e.state) : "nodata"}`;
    cell.title = `${e.name} — ${e.state ? STATE_LABEL[e.state] : "not probed yet"}`;
    cell.setAttribute("aria-label", cell.title);
    cell.addEventListener("click", () => {
      const row = document.getElementById(`row-${e.id}`);
      if (!row) return; // filtered out of the list — dimmed, not clickable-to-nowhere
      row.scrollIntoView({ block: "center", behavior: "smooth" });
      row.focus();
    });
    cells.set(e.id, cell);
    frag.append(cell);
  }
  container.append(frag);
}

export function updateMosaic(visibleIds) {
  for (const [id, cell] of cells) {
    cell.classList.toggle("mosaic__cell--dimmed", !visibleIds.has(id));
  }
}
```

```js
export function summarise(entries, generated) {

  const answered = measured.filter((e) => ["ok", "gated"].includes(levelOf(e.state))).length;
```
